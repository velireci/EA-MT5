# T004 M15 observer - first bounded round

This is a pure component and controlled-data script, NOT a new EA. Keep using the verified T003 EA for H4 observations. Nothing here places orders or selects the client's M15 structural level automatically.

## Run the script
Use the compiled T004_LogicTest.ex5 under MQL5/Scripts (Navigator -> Scripts -> Refresh), attach to any chart, and copy the final `T004 LOGIC TEST finished` line from Experts. Chart prices and timeframe do not affect its synthetic inputs. MetaEditor compilation and MT5 execution are different evidence.

To compile sources yourself, preserve the layout: src/tests/T004_LogicTest.mq5 beside src/include/. The two new headers use the existing H4Bias.mqh and H4Structure.mqh from base 6676a01. Compile the mq5, not a header by itself.

## Component API
`M4Init(state, candidates, events)` defaults to M4_POLICY_UNSET. For controlled experiments only, pass M4_A_AT_OR_AFTER_BREAK explicitly. This is a timing PROPOSAL, not a client decision.

`M4SetContext(context, observed_at, state, candidates, events)` receives a reliable/ready context, explicit source selection and H4 setup/FVG identity. `valid_from` is the close of the touching H4 candle, not its opening. Late observation delays M15 activation to observation time; elapsed M15 bars are not retrospectively permitted.

`M4ContextFromH3(h3_context, reliable, out, selected_source=false)` is the optional adapter. The caller obtains h3_context from H3SetupContext and reliability from that same evaluation. Default source selection is false; opting in labels the source T003_PROTOTYPE. The adapter does not decide that T003 bias outranks T002 direction. Ordinary H4 context can be supplied using SM4Context when the upstream touch observer exists.

`M4Step(closed_m15_bar, asof, level, state, candidates, events)` reads only the supplied bar. Level.valid means the caller has selected an ACTIVE, not already body-broken, proposed M15 structural level; known must be at/before the evaluated bar's open. The observer does not verify the pre-context history of that level or choose it from swings. Without it the module stays WAIT_BREAK. All bars must be chronological; C cannot touch its own FVG, and gaps cannot form a three-bar FVG across missing intervals.

The states are WAIT_CONTEXT, WAIT_POLICY, WAIT_BREAK, WAIT_FVG, WAIT_RETURN, RETURN_OBSERVED and REPLAY_REQUIRED. RETURN_OBSERVED is only a candle-intersection fact. There is no order-ready flag, selected entry boundary, SL or TP.

## Caller obligations and limits
- Feed the H4 context known at each time, then the subsequent closed M15 bars. Do not feed the final H4 snapshot across its earlier history. Context loss, FVG replacement or a new reconfirmation time resets M15 progress.
- An unchanged snapshot does not reset the observer. Any supplied change in direction source/setup/direction/FVG identity/bounds/confirmation/valid_from starts a new epoch.
- Changed high/low/close of an already consumed bar, out-of-order input or observation-time rollback requires full replay; even malformed revisions revoke previous candidates. Open/volume/spread are not used by this observer. Revisions older than the last bar are caught if resubmitted; the module does not poll history for undisclosed revisions.
- Start a new observer and replay with historical context updates to repair data. Baseline replayed events before live notification. These live orchestration/persistence duties are not implemented here.
- Missing M15 intervals conservatively reset M15 progress and skip BOS on the first bar after the gap. This includes weekend gaps and is a technical proposal.
- All qualifying M15 FVGs are reported, none selected as the entry zone. The opt-in timing uses A at/after the BOS bar; no size/displacement filter or expiry was invented.

## Experimental selector helper (second round)
`M4SelectSwingProposal(bars, n, direction, result, enabled=false, left=2, right=2, lookback=300)` adds an optional source of proposed levels. Pass ONLY earlier closed bars in prefix n; the evaluated crossing bar must not be in that prefix. The default leaves result.status DISABLED and result.level.valid false. Enable only for explicit development experiments, not as a client-approved MSS definition.

It selects the most recent confirmed unbroken high for BUY or low for SELL. A previous strict body close consumes a level; a wick or equality does not. If the newest was consumed, an older unbroken one can be selected. Lookback applies to the prior prefix and only its last contiguous M15 segment is used; no swing spans a gap. Results report window_start, used, pivot, confirmation, ambiguous count and SELECTED / NO_LEVEL / SHORT_HISTORY / INVALID_INPUT. Values older than the bounded window are unknown, not proved absent. Changing parameters requires a new experiment/replay; no live state is persisted here.
