# T004 M15 observer - first bounded round

This is a pure component and controlled-data script, NOT a new EA. Keep using the verified T003 EA for H4 observations. Nothing here places orders or selects the client's M15 structural level automatically.

## Run the script
Use the compiled T004_LogicTest.ex5 under MQL5/Scripts (Navigator -> Scripts -> Refresh), attach to any chart, and copy the final `T004 LOGIC TEST finished` line from Experts. Chart prices and timeframe do not affect its synthetic inputs. MetaEditor compilation and MT5 execution are different evidence.

To compile sources yourself, preserve the layout: src/tests/T004_LogicTest.mq5 beside src/include/. The two new headers use the existing H4Bias.mqh and H4Structure.mqh from base 6676a01. Compile the mq5, not a header by itself.

## Component API
`M4Init(state, candidates, events)` defaults to M4_POLICY_UNSET. For controlled experiments only, pass M4_A_AT_OR_AFTER_BREAK explicitly. This is a timing PROPOSAL, not a client decision.

`M4SetContext(context, observed_at, state, candidates, events)` receives a reliable/ready context, explicit source selection and H4 setup/FVG identity. `valid_from` is the close of the touching H4 candle, not its opening. Late observation delays M15 activation to observation time; elapsed M15 bars are not retrospectively permitted.

`M4ContextFromH3(h3_context, reliable, out, selected_source=false)` is the optional adapter. The caller obtains h3_context from H3SetupContext and reliability from that same evaluation. Default source selection is false; opting in labels the source T003_PROTOTYPE. The adapter does not decide that T003 bias outranks T002 direction. Ordinary H4 context can be supplied using SM4Context when the upstream touch observer exists.

`M4Step(closed_m15_bar, asof, level, state, candidates, events)` reads only the supplied bar. Level.valid means the caller has selected an ACTIVE, not already body-broken, proposed M15 structural level; known must be at/before the evaluated bar's open. The observer does not verify the pre-context history of that level or choose it from swings. Without it the module stays WAIT_BREAK. All bars must be chronological; C cannot touch its own FVG, and gaps cannot form a three-bar FVG across missing intervals.

The states are WAIT_CONTEXT, WAIT_POLICY, WAIT_BREAK, WAIT_FVG, WAIT_RETURN, RETURN_OBSERVED and REPLAY_REQUIRED. RETURN_OBSERVED is only a candle-intersection fact. There is no order-ready flag, selected entry boundary, SL or TP.

## Caller obligations and limits
- Feed the H4 context known at each time, then the subsequent closed M15 bars. Do not feed the final H4 snapshot across its earlier history. Context loss, FVG replacement or a new reconfirmation time resets M15 progress.
- An unchanged snapshot does not reset the observer. Any supplied change in direction source/setup/direction/FVG identity/bounds/confirmation/valid_from starts a new epoch.
- Changed high/low/close of an already consumed bar, out-of-order input or observation-time rollback requires full replay; even malformed revisions revoke previous candidates. Open/volume/spread are not used by this observer. Revisions older than the last bar are caught if resubmitted; the module does not poll history for undisclosed revisions.
- Start a new observer and replay with historical context updates to repair data. Baseline replayed events before live notification. These live orchestration/persistence duties are not implemented here.
- Missing M15 intervals conservatively reset M15 progress and skip BOS on the first bar after the gap. This includes weekend gaps and is a technical proposal.
- All qualifying M15 FVGs are reported, none selected as the entry zone. The opt-in timing uses A at/after the BOS bar; no size/displacement filter or expiry was invented.

## Experimental selector helper (second round)
`M4SelectSwingProposal(bars, n, direction, result, enabled=false, left=2, right=2, lookback=300)` adds an optional source of proposed levels. Pass ONLY earlier closed bars in prefix n; the evaluated crossing bar must not be in that prefix. The default leaves result.status DISABLED and result.level.valid false. Enable only for explicit development experiments, not as a client-approved MSS definition.

It selects the most recent confirmed unbroken high for BUY or low for SELL. A previous strict body close consumes a level; a wick or equality does not. If the newest was consumed, an older unbroken one can be selected. Lookback applies to the prior prefix and only its last contiguous M15 segment is used; no swing spans a gap. Results report window_start, used, pivot, confirmation, ambiguous count and SELECTED / NO_LEVEL / SHORT_HISTORY / INVALID_INPUT. Values older than the bounded window are unknown, not proved absent. Changing parameters requires a new experiment/replay; no live state is persisted here.

To test, run compiled T004_SelectorTest under MQL5/Scripts. The separate T004_LogicTest at 51884ec already passed 49/0 in the owner's MT5. A pass of SelectorTest would check this implementation on synthetic data, not which swing the client meant.

## Read-only observer EA (third round)
XauUsdM15Observer reads real H4/M15 histories but never trades. It connects ONLY the T003 RECONFIRMED context path; ordinary H4-touch setups remain unfinished. It does not resolve direction disagreement, choose an entry edge or represent a complete entry engine.

First run T004_TimelineTest.ex5 under MQL5/Scripts and send its final Experts line. Then copy XauUsdM15Observer.ex5 under MQL5/Experts, refresh Navigator and attach on a NEW XAUUSD M15 chart. The existing T003 chart can remain unchanged. Each chart owns its own objects; this EA removes only velo_t004_.

All three choices default UNSELECTED. To observe the already documented technical proposals explicitly choose:
- InpContextSource = M4_T003_RECONF_PROPOSAL.
- InpM15Level = M4_LATEST_FRACTAL_PROPOSAL.
- InpFvgTiming = M4_A_AFTER_BOS_PROPOSAL (candle A may be the BOS candle).
- For the first historical observation: InpAsOfTime = 2026.10.06 00:00:00, broker/server time; H4 Rebuild 2000, H4 Lookback 300, M15 Replay 512, M15 Lookback 300, Left/Right 2/2. These dates are a review example, not strategy constants.

Wait for the loading message to finish. Send the panel and Experts lines T004 REPLAY SUMMARY / CONTEXT / FACT. No fixed M15 outcome is promised: it depends on the terminal's actual history. The known H4 context at that cutoff should be checked against the earlier T003 observation. No live price is used in historical mode; later chart candles can remain visible but are not read by the replay.

InpAsOfTime=0 selects live closed-bar replays. Data failure/desynchronisation clears results; recovery reconstructs them. Every event is deliberately labelled REPLAY, not NEW. Replays are not notifications or entries. Live direction/source choice remains explicitly a proposal, even when H4 reliability is CONVERGED.

Requested history: M15 Replay + M15 Lookback closed bars (default 812) at the cutoff, plus enough H4 history for a full rebuild at the first replayed M15 bar. Partial copies show loading and retry; lower the replay depth only as an explicit review change, never interpret loading as no market setup. Replay cost is printed in ms after execution and has not yet been measured in MT5.

Gold line is a NEXT-bar candidate, orange line is the recorded broken-level proposal. A just-confirmed NEXT level may be projected one M15 interval to make it visible; this is a level projection, not a future candle. M15 FVG rectangles are outlines, dashed after a return fact. Source/timing/unreliable gates can leave the chart empty with a status explanation. Historical mode stays static after a successful build; re-attach after changing broker history. Live copies/replays occur at new boundaries or recovery, not every tick. A valid older-bar revision is discovered only when that history is copied again; no NEW-event claim is made.

EA v1.01 corrects a restart-cache defect observed when changing the chart from H4 to M15: previously state reset but the old successful-copy marker could skip historical rebuilding. The fix resets both together. After installing v1.01, keep the same opt-ins/as-of, switch M15 -> H4 -> M15 and verify that a new REPLAY SUMMARY appears after each restart and that context/BOS/fact counts reconstruct consistently. This retest is still required; no logic/strategy definition was changed.

## Ordinary H4 FVG-touch source (fourth round, PROPOSAL)
XauUsdM15Observer v1.02 can feed the unchanged M15 mechanism from a second, DISTINCT context source. Nothing is selected by default.

### Select the source
InpContextSource (one source per run, never combined or prioritised):
- M4_SOURCE_UNSELECTED (default): contexts are produced unselected, the observer blocks.
- M4_T003_RECONF_PROPOSAL: T003 RECONFIRMED context, source id T003_PROTOTYPE (unchanged behaviour).
- M4_T002_TOUCH_AFTER_LOSS_PROPOSAL: ordinary H4 FVG touch, source id T002_H4_TOUCH_PROPOSAL; after a record is lost any valid IRL FVG (also a previously recorded one) can be recorded again.
- M4_T002_TOUCH_FIRST_ONLY_PROPOSAL: same, but an FVG id is recorded at most once per scan.
The M15 level (InpM15Level) and the FVG timing (InpFvgTiming) stay separate opt-ins and must also be chosen. New input InpOrdinaryWarmBars (default 120, 10..1000): H4 closes scanned BEFORE the replay start so that a touch recorded before it can be recovered; H4 history needed is InpH4LookbackBars + InpOrdinaryWarmBars. InpH4LookbackBars is the analysed window (T002 lookback, 50..1000).

### What the ordinary path does (reuse of T002; the proposals are marked P)
1. At every H4 close the analysis uses only the last window closed bars (never the final H4 state for an earlier moment): swings 2/2, direction, interval, FVG, IRL class, ERL state, all from H4Structure.mqh unchanged.
2. Before the touching candle opens (prefix to the previous close) the setup must be active (trending direction, valid interval, ERL UNTOUCHED, a selectable IRL candidate) and the FVG must be a FRESH/TOUCHED same-direction IRL candidate. Its three candles therefore closed at or before the touching candle's open. A candle opening exactly at the confirmation time can touch; candle C itself cannot.
3. The touching candle's wick range must intersect the zone (inclusive). Candidates are taken in T002 nearest-first order from the last closed close (P: reference price, OD4).
4. The record is made at the CLOSE of the touching candle: valid_from = open + 4h. It exists only if the same FVG is still a valid IRL candidate with active setup after that candle (a close strictly beyond the far edge on the touching candle wins: no record; the next candidate is tried).
5. M15 (unchanged): bars opening before valid_from are not used. The M15 bar ending exactly at the H4 close is excluded; the bar opening then is usable after its own close. At equal closing times the H4 change is applied before the M15 bar (revocation and replacement included).
6. P (OD1, OD2): an open record is not changed by later touches. It is revoked at the first H4 close where the post-close state no longer holds: TREND_CHANGE (T002 direction no longer the same trend), FVG_INVALID, INTERVAL_LOST, ERL_TAKEN, NOT_IRL (interval moved so the zone is outside), FVG_NOT_IN_WINDOW, HISTORY_PARTIAL. If another valid candidate is touched on the revoking candle, it replaces the record at the same close (REPLACE; one update per close). The strict rule can revoke an in-progress M15 sequence when a new H4 swing moves the interval; the lenient alternative is an open decision.
7. P (OD3): re-touch after a loss follows the chosen enum value. P (OD6): no expiry by bar count.

### Display and log
Title and the Source line name the source id. Ordinary mode shows `SOURCE DISAGREEMENT` (tomato) when the T002-based context direction differs from the T003 bias at the touch or now, else `T003 view`; T003 mode shows `MODEL DISAGREEMENT` for T002 baseline versus T003 as before plus `ctx vs T002`. The flag never resolves the contradiction and never changes which source feeds M15. Log lines: `T004 REPLAY ORDINARY` (scan summary, T003 at touch and now), `T004 REPLAY H4TOUCH` (recent record/revocation notes), `T004 REPLAY CONTEXT`, as before the REPLAY SUMMARY and FACT lines. All remain REPLAY, never NEW, never trade signals.

### Limits
- H4 records are recovered from a bounded warm-up; an older touch is not seen. The sliding window drops old swings exactly like the T002 map.
- Historical mode stays static after a successful build; live repeats the closed-bar replay at M15/H4 boundaries.
- The M15 prices are independent of the H4 zone prices (the observer never compares them). A RETURN_OBSERVED inside or outside the H4 zone is not distinguished.

- Test: `T004_OrdinaryTest.ex5` under MQL5/Scripts; the final line is `T004 ORDINARY TEST finished: N passed, M failed`.
