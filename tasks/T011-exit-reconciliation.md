# T011 part 3 - reconciliation of the partial-close request (pure)

Branch `codex/t004-m15-confirmation` (PR #4), base `d83426a`. Writer: Claude. Relayed (Codex / owner, NOT my runs): activation verified at `d83426a` - Codex Python 12/0, MetaEditor 0/0, owner MT5 ActivationTest 1010/0. Codex reviews and compiles the new files; the owner runs MT5.

Scope: judge a caller-supplied SNAPSHOT against the request kept in the activation state and, only through this function, apply the permitted transition. No broker read, no order, no retry, no persistence, no restart guarantee, no BE/costs, no EA wiring. It never produces a request and never changes the 80/20 plan (initial_steps, request_steps, request_id, volume_step, position_id are untouched; asserted by tests).

DESIGN DECISION (documented as requested): ONE source of state. `ER_Reconcile` / `reconcile` is a CONTROLLED TRANSITION on the SAME `SEaState` that ExitActivation owns, not a second state machine and not a decision-only helper. Decision -> transition: CONFIRMED -> DONE (the only way out of NEEDS_RECONCILIATION; a quote or a plain report still cannot do it), PARTIAL -> NEEDS_RECONCILIATION (executed steps recorded), BLOCK -> BLOCKED, NOT_EXECUTED / UNKNOWN / INVALID_INPUT -> no change (a DONE state that fails the re-check goes to NEEDS_RECONCILIATION, or BLOCKED on proof of a conflict). ExitActivation, ExitSplit and the T006 grid (PS_GridSteps) are reused, not copied or changed.

Snapshot (supplied): position_found, position_id, request_id, volume_step, volume_current, up to 16 executions (exec_id, request_id, volume), executions_complete.
Rules: executions are identified by exec_id and de-duplicated inside the snapshot (same id, request and volume = one execution; the same id with another request or volume = BLOCK); steps are recomputed from every snapshot, never accumulated, so repeating a snapshot never counts an execution twice; only executions linked to the request id count. A volume drop alone never proves our request executed: with no linked execution a changed position is UNKNOWN (list incomplete) or BLOCK (list complete: volume changed without a linked execution).
DONE only when the linked executions equal the requested steps exactly AND the position equals initial - requested on the request grid. Partial linked fills stay for reconciliation (PARTIAL). Overfill, another step, wrong position, wrong request id, a missing position (no match possible), an off-grid execution or a position mismatch after a full fill BLOCK. A late fill after TIMEOUT (or after an explicit REJECTED) is accepted only through this reconciliation, with evidence that names the request.

Limits: the snapshot is only as true as the caller makes it; `executions_complete` is the caller's claim; no guarantee after a restart; not atomic; the policy for SPLIT_POLICY_UNSET and for TP == 2R stays open; nothing says how the snapshot is obtained from the broker.
